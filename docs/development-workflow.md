# 开发协作与对话分工

本文记录项目维护者与开发助手的协作约定，不属于面向使用者的运行说明。
插件技术接口统一见 [任务插件实现说明](plugin-development.md)，避免在此重复维护。

## 框架维护对话

当前框架对话持续处理公共能力，包括：

- 任务接口、加载、配置解析、结果状态和执行策略。
- 日志、通知、退出码以及未来的调度、重试、总超时等能力。
- 公共依赖及 CI 环境的统一管理。
- 对插件接口产生影响的变更和兼容方案。

## 独立模块对话

每个具体站点模块使用独立对话，主要修改：

- `plugins/<模块类型>/` 中的实现、配置模型和模块 README。
- `tests/test_<模块类型>*.py` 中的离线测试。

模块对话开始时先阅读插件实现说明，并以当前接口源码为准。
不为接入单个站点直接修改框架公共代码或其他插件；遇到缺失的公共能力，
记录使用场景、接口需求和影响范围，由维护者带回框架对话协调。
新增第三方依赖同样先列明用途和版本需求，再统一调整依赖与运行环境。

保留已有本地配置、未提交改动和其他对话的工作。优先使用离线模拟测试，
真实登录或签到按维护者指定的联调范围执行。交付时说明测试结果和未验证事项；
提交、推送及跨对话发消息均按维护者的明确指令执行。

## 新模块对话的交接模板

复制以下内容到新对话，并补充站点资料和目标行为：

> 请先阅读 docs/plugin-development.md 和 docs/development-workflow.md，
> 按当前接口实现 `<模块类型>` 插件。
> 站点资料与目标行为：……
> 主要改动限定在 plugins/<模块类型>/ 和相应测试，模块 README 中提供配置说明。
> 保留现有业务失败与程序异常的区分，不修改框架公共能力或其他插件。
> 需要公共能力或新增依赖时，说明具体需求及影响，交由框架维护对话协调。
> 使用离线模拟测试；真实站点联调范围由我另行指定。
> 完成后说明改动、测试结果、未验证事项，不自动提交或推送。

这份文档仅记录协作方式，不会自动创建对话、发送消息或启动任务。
